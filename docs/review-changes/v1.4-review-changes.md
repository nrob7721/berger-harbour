# Improvements

1. Superseded booking - there should be a way for staff to reactivate a superseded booking when the customer attempts to reorganise. Similar to how an Expired status bookings have a message to reactivate with a manual payment. There should be a message that indicates the booking was superseded and they just need to change the dates to reactivate it. When it is reactivated, it should become another standby booking
1. Staff booking Manual payments
    1. Manual payments can still be created/saved independently of booking dialog "Save Changes" button. We want to align it with add on behaviour where the payments are only saved upon clicking "Save Changes"
    1. Add remove payment button - against each payment row, we need a Remove button in a 5th column next to the Note
    1. Validation - add both frontend and server side domain validation for the following:
        1. A payment cannot be BEFORE the creation date of the booking
        1. A payment cannot be in the future, it must be limited to today only
1. Add a refresh button to allow user to manually check for updates on the Bookings calendar. When clicked, a spinner next to it shows data is being retrieved
1. Currently, if the booking month was cached and it is still running a call in the backend, there's no way to know. Show a spinner somewhere to indicate data is being retrieved. Same spinne
1. Staff New Booking
    1. When searching existing customer after entering email, show spinner to indicate customer search is in progress. Also, disable the other customer fields while searching
1. Customer booking
    1. Entire Guests and features moved up to the top, below "Choose your dates and boats" above the "Type of stay" radio buttons
    1. Allow customer to click on booking steps directly to go jump/go back instead of just the Back button
    1. Type of stay radio button adjustment
        1. Current behaviour: there is a single radio button for full week selection. The only days selectable are Mondays and Fridays. This is to clarify whether a click to Thursday is a Mon - Mon booking or a Fri - Fri booking. However, the greyed days inbetween could be perceived as unavailable
        1. Solution: inside the Week radio button frame, we will have 2 different radio buttons "Week (Fri - Fri)" and "Week (Mon - Mon)". This way the Week behaviour can be like the other options i.e. the customer can select any day and the range will be auto selected
    1. Custom dates info message - underneath the radio buttons, we want an info message that says something like "For custom date periods call <business settings number> to arrange". This data should already be available on this page
    1. Selected boat functionality
        1. Change to "Show <selected boats>'s availability only" - instead of a checkbox, just an info message saying "Currently showing availabilities for <selected boat>, click here to see all availabilities". 'click here' should be a hyperlink text that when clicked, simply deselects the currently selected boat
        1. Currently selected boat - remove the checkbox and just show the whole boat card as selected. 
        1. When the selected boat is clicked again, it should be deselected and the calendar should show all availabilities
1. Boat ordering - system wide change; instead of ordering by berth descending, order by price descending. Based on the Normal season prices
